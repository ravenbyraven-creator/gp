BUILD PROMPT — Inbox v2 (Lifecycle + Random Messages + Folders + Reply as GM)
You are working in the Gorilla Position monorepo. Implement everything below in one PR. Do NOT use emojis anywhere in code, comments, UI strings, or message templates. Match the existing code style. This entire feature must use ZERO OpenAI tokens — all message generation is local templated.

Part 0 — Architecture overview
Today the inbox is 100% derived from history entries via buildMessages in gp/artifacts/universe-mode/src/components/WrestlerInbox.tsx. Read state lives in umc.inboxReadIds. Nothing else exists.

This PR adds:

A second message source: a local scheduler that generates random talent + non-talent messages on each Advance, stored in umc.inboxGenerated. Zero tokens.
Lifecycle: archive, delete, star, mark unread, bulk actions, search.
Folders/filters by sender type and state.
Reply as GM: pick a template response, it becomes a Night Note in history and triggers an auto-reply from the wrestler.
The combined inbox view = (derived from history) PLUS (umc.inboxGenerated) MINUS (umc.inboxArchivedIds + umc.inboxDeletedIds), with starred floated to top.

Part 3 — The scheduler
In gp/artifacts/universe-mode/src/lib/inbox.ts, add:

export function generateInboxMessagesOnAdvance(args: {
  roster: Wrestler[];
  championships: Championship[];
  history: RivalryEntry[];
  events: PremiumEvent[];
  prior: UniverseDate;
  next: UniverseDate;
  lastFire: Record<string, number>;
  templates: InboxTemplate[];
}): {
  newMessages: GeneratedInboxMessage[];
  nextLastFire: Record<string, number>;
};
Rules:

Hard cap: at most 3 messages per Advance call, no matter what.
Compute daysSinceLastBooking per wrestler from history (look for any storyline/show/promo entry mentioning them).
Compute daysSinceLastMessage per template+sender combo from lastFire.
For each template, find every wrestler/sender for which eligible(ctx) === true and cooldownDays has passed.
Weighted-random pick (using the template's weight) to fill the 3 slots. Bias to variety: never pick the same template twice in one Advance, never pick the same wrestler twice in one Advance.
Include at least 1 non-talent message per Advance if any non-talent template is eligible.
Update lastFire keyed by ${templateId}:${fromName}.
Add unit tests in gp/artifacts/universe-mode/src/lib/inbox.test.ts covering: cap of 3, cooldown enforcement, eligibility filtering (idle vs active wrestler), weighted randomness with seeded RNG, never-twice-same-wrestler.

Part 4 — Wire scheduler into Advance

const { newMessages, nextLastFire } = generateInboxMessagesOnAdvance({

6b. What happens on Send
On confirm:

Build the reply text (template body or custom textarea).
Create a new history entry of kind: "log":
const note: RivalryEntry = {
  kind: "log",
  id: crypto.randomUUID(),
  createdAt: Date.now(),
  universeDate,
  text: `[GM Reply to ${msg.from}] ${replyText}`,
};
Push to useHistory().
If the recipient is a roster wrestler AND has any active rivalry, append note.id to that rivalry's historyEntryIds (use existing useRivalries). If multiple active rivalries, pick the one with the most recent lastActivityDate.
Save a GMReply entry to umc.inboxReplies linking it back: { messageId, templateId, bodyText, createdNightNoteId: note.id, at: Date.now() }.
Generate an auto-reply InboxMessage from the wrestler back to the GM, using a small set of alignment-aware ack templates:
HEEL: "Good. Don't waste my time. — {Wrestler}"
FACE: "Appreciate it. Won't let you down. — {Wrestler}"
TWEENER: "We will see how this plays out. — {Wrestler}"
For non-talent senders: skip the auto-reply. Push to useInboxGenerated() with isAutoReply: true and inReplyToId: msg.id.
Mark the original message as read (add to inboxReadIds).
Toast: "Reply filed as canon. {Wrestler} acknowledged."
Close the sheet.
