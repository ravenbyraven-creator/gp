Step 5 — Write the localStorage migration
Existing users have umc.roster in localStorage from previous sessions. Some of those entries may have custom uploaded images (data URIs in imageUrl). The migration rules:
In artifacts/universe-mode/src/lib/storage.ts (in useRoster or wherever the roster is initialized from localStorage):

On first load after this update, iterate every wrestler in the user's existing roster.
For each, find the matching seed entry by case-insensitive name match.
If the user's wrestler has NO imageUrl set, AND the seed has an imageUrl, copy the seed's imageUrl over.
If the user's wrestler ALREADY has an imageUrl (custom upload from the Roster UI — these are typically data:image/... URIs), DO NOT touch it. Custom uploads always win.
If the user's wrestler has imageUrl: "/wrestlers/..." (already migrated from a previous session), leave it alone.

Use a one-time guard so the migration doesn't re-run on every page load. A simple approach: write a umc.rosterPhotosMigrated: true flag to localStorage after running. Skip if already set.
Save the updated roster back to localStorage.
